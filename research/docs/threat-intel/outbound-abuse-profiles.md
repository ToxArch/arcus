# Outbound Abuse Profiles & Amplification Mechanics

This dossier analyzes outbound network abuse generated by compromised residential broadband hosts, detailing the amplification factors, packet characteristics, and regulatory exposure.

---

## 2. Amplification Factor Mathematics

The Amplification Factor ($AF$) of an outbound or reflected abuse stream is mathematically defined as:
$$AF = \frac{\sum \text{Bytes}_{\text{amplified\_response}}}{\sum \text{Bytes}_{\text{trigger\_request}}}$$

For an ISP where residential ONTs or routers are misconfigured as Open Resolvers (DNS) or open UPnP/SSDP responders:
- A malicious external attacker sends a stream of $1 \text{ Gbps}$ of spoofed requests toward the ISP's subscriber subnet.
- The subscriber ONTs reflect this traffic outward toward the victim with $AF = 40$:
  $$\text{Outbound Transit Flood} = 1 \text{ Gbps} \times 40 = 40 \text{ Gbps}$$
- **Impact on ISP:** Complete saturation of upstream IP transit links, massive transit billing overages (95th percentile burst billing), and immediate upstream BGP blackholing.

## 3. BCP 38 / RFC 2827 Ingress Filtering Imperative

The root cause of IP spoofing-based amplification attacks is the failure of access networks to implement **BCP 38 (Best Current Practice 38: Ingress Filtering for Multihomed Networks)**:
- **Rule:** A network must never forward a packet whose source IP address does not belong to the prefix allocated to that specific interface or subscriber.
- In PPPoE topologies, the BNG automatically enforces source address validation because PPP packets are encapsulated inside point-to-point tunnels tied to the subscriber's assigned IP.
- In IPoE / DHCP networks, access switches and BNGs must enforce **IP Source Guard (IPSG)** and **Unicast Reverse Path Forwarding (uRPF Strict Mode)** to prevent compromised hosts from launching spoofed amplification attacks.
