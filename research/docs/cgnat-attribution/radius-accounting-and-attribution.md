# RADIUS Accounting & Two-Tier Temporal Attribution

This dossier specifies the accounting telemetry schema and the exact temporal intersection algorithms required to resolve an external public abuse report down to an authenticated physical subscriber line.

---

## 1. AAA Telemetry & RADIUS Accounting Lifecycle

Broadband access routers (BNGs) communicate subscriber state to centralized AAA infrastructure (FreeRADIUS / Radiator) via the Remote Authentication Dial-In User Service (RADIUS) protocol (RFC 2865, RFC 2866).

### Mandatory Accounting Information Elements:

| RADIUS Attribute ID | Attribute Name | Protocol Significance | Attribution Role |
| :--- | :--- | :--- | :--- |
| **1** | `User-Name` | Broadband customer account identifier (e.g., `user_blr_4921@corp`). | Canonical customer identity linking to KYC and billing records. |
| **4** | `NAS-IP-Address` | IP address of the terminating BNG router. | Physical BNG PoP location. |
| **8** | `Framed-IP-Address` | CGNAT private IPv4 address assigned to subscriber (e.g., `100.64.14.88`). | **Primary pre-NAT identity anchor.** |
| **31** | `Calling-Station-Id` | Physical MAC address of customer ONT / router. | Hardware binding; identifies device swaps. |
| **87** | `NAS-Port-Id` | Physical/logical interface on BNG (e.g., `ether2.100:1042` or `vlan-402`). | Physical access loop, OLT PON port, and C-VLAN/S-VLAN binding. |
| **40** | `Acct-Status-Type` | Packet type: `Start(1)`, `Stop(2)`, `Interim-Update(3)`. | Defines temporal state window. |
| **44** | `Acct-Session-Id` | Unique 64-bit session identifier generated by BNG. | Session lifecycle correlation key. |
| **42** | `Acct-Input-Octets` | Inbound bytes transferred across session. | Verification of active traffic generation. |
| **43** | `Acct-Output-Octets` | Outbound bytes transferred across session. | Verification of active traffic generation. |
| **46** | `Acct-Session-Time` | Elapsed seconds since session start. | Temporal sanity validation. |
| **49** | `Acct-Terminate-Cause` | Cause of session termination (e.g., `User-Request`, `Lost-Carrier`, `Admin-Reset`). | Investigating sudden drops during active attacks. |

## 2. Two-Tier Temporal Attribution Algorithm

An external abuse notice (from CERT-In, Spamhaus, Team Cymru, or a compromised victim) provides an incident tuple:
$$\mathcal{T}_{incident} = \langle IP_{pub}, Port_{pub}, t_{incident} \rangle$$

To identify the subscriber, the system executes a **two-tier temporal intersection query**:

```
[External Abuse Tuple]
(IP_pub, Port_pub, t_incident)
          |
          v
[Tier 1: CGNAT PBA Table]
Find entry where:
  - Public_IP == IP_pub
  - Port_Start <= Port_pub <= Port_End
  - Alloc_Time <= t_incident <= Release_Time
          |
          +--> Output: Framed-IP-Address (100.64.x.y)
          |
          v
[Tier 2: RADIUS radacct Table]
Find entry where:
  - Framed-IP-Address == 100.64.x.y
  - Session_Start <= t_incident <= Session_Stop
          |
          +--> Output: User-Name, Calling-Station-Id, NAS-Port-Id, Physical Loop
```

### Tier 1 Mathematical Formulation (CGNAT Inversion):
Let $\mathcal{B}$ represent the set of all Port Block Allocation records:
$$\mathcal{B} = \{ b_i = \langle IP_{pub}^{(i)}, P_{start}^{(i)}, P_{end}^{(i)}, IP_{priv}^{(i)}, t_{alloc}^{(i)}, t_{release}^{(i)} \rangle \}$$

The private address $IP_{priv}^*$ at $t_{incident}$ is the unique solution satisfying:
$$IP_{priv}^* = \left\{ IP_{priv}^{(i)} \;\middle|\; IP_{pub}^{(i)} = IP_{pub} \;\land\; P_{start}^{(i)} \le Port_{pub} \le P_{end}^{(i)} \;\land\; t_{alloc}^{(i)} \le t_{incident} \le t_{release}^{(i)} \right\}$$

### Tier 2 Mathematical Formulation (RADIUS Session Inversion):
Let $\mathcal{S}$ represent the set of all RADIUS accounting sessions:
$$\mathcal{S} = \{ s_j = \langle \text{User}_j, IP_{framed}^{(j)}, \text{MAC}_j, t_{start}^{(j)}, t_{stop}^{(j)}, \text{Status}_j \rangle \}$$

The verified subscriber identity $\text{User}^*$ is:
$$\text{User}^* = \left\{ \text{User}_j \;\middle|\; IP_{framed}^{(j)} = IP_{priv}^* \;\land\; t_{start}^{(j)} \le t_{incident} \le t_{stop}^{(j)} \right\}$$

## 3. Orphaned Session & Clock Skew Recovery

In real-world carrier operations, power outages, fiber cuts, or router kernel panics prevent the BNG from dispatching an `Acct-Status-Type = Stop` packet. This produces an **orphaned session** where $t_{stop}$ remains `NULL` indefinitely.

### Failure Risk:
If an orphaned session is not resolved, multiple subscribers who are subsequently assigned the same private IP address appear to overlap in the attribution database, creating ambiguity that invalidates legal evidence under **Bharatiya Sakshya Adhiniyam, 2023 (BSA Section 63)**.

### Mathematical Recovery via Interim Keepalives:
RADIUS `Acct-Interim-Interval` is configured to $\Delta t_{interim} = 300 \text{ seconds}$ (5 minutes).
Each interim update refreshes the `Acct-Session-Time` and `Acct-Last-Updated` timestamp.

For any session where $t_{stop} \text{ is NULL}$:
$$t_{effective\_stop} = \min\left(t_{now}, \; t_{last\_interim} + 2 \times \Delta t_{interim}\right)$$

If an abuse timestamp $t_{incident}$ occurs after $t_{last\_interim} + 2 \times \Delta t_{interim}$, the orphaned session is mathematically excluded:
$$t_{incident} > t_{effective\_stop} \implies \text{Session Discarded (Lapsed)}$$

### Clock Skew Tolerance:
All BNG and AAA collectors synchronize against **National Physical Laboratory of India (NPLI) Stratum-1 NTP sources**.
To account for network jitter:
$$t_{query\_window} = \left[ t_{incident} - \delta_{skew}, \; t_{incident} + \delta_{skew} \right] \quad \text{where } \delta_{skew} = 2.0 \text{ seconds}$$
